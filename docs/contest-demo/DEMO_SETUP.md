# 공모전 데모 실행·독립 배포

저장소 기준 Node.js 22와 npm을 사용합니다. 저장소 루트에서 실행합니다.

```sh
npm ci
npm run demo:build
npm run demo:preview -- --port 4176
```

브라우저에서 `http://localhost:4176/`을 엽니다. Codex Cloud에서는 같은 환경의 브라우저에서 열 수 있습니다. 포털 URL이 이미 설정된 환경에서는 실행 포트에 대응하는 인증된 HTTP 미리보기 URL을 사용합니다. 개발 중에는 `npm run demo:dev -- --port 4176`을 사용할 수 있습니다. 데모 개발 서버는 HMR을 끄므로 편집 후 브라우저를 새로고침합니다. 발표와 네트워크 검증은 빌드 미리보기로 진행합니다.

- 상단 `시연 제어`에서 가상 역할 또는 A~D 시나리오를 선택합니다. 역할 버튼은 운영 인증을 호출하지 않습니다.
- 같은 탭의 화면 이동, 역할 전환, 뒤로가기·앞으로가기에서는 데이터가 유지됩니다. 브라우저 탐색은 URL을 바꾸며 역할은 현재 선택을 유지합니다. 현재 역할의 메뉴 범위 밖 URL에는 안내가 표시됩니다.
- 새로고침 시 일반 교직원 역할과 모든 가상 데이터가 초기화됩니다. 열린 경로는 유지되므로 관리자 페이지에서 새로고침했다면 다시 역할을 선택합니다.
- `가상 검사 초기화`는 학급 일정만 복원합니다. `전체 데모 데이터 초기화`는 일반 교직원 홈으로 이동하며 모든 데이터를 최초 값으로 복원합니다.
- 별도검사의 시연 시계는 2026년 11월 26일 09:15 한국 시간부터 버튼을 누를 때마다 1분 진행합니다. 공유 화면은 마지막 갱신 시각을 브라우저 시간대로 표시합니다. 발표용 브라우저 시간대는 Asia/Seoul을 사용합니다.

## 독립 Vercel 프로젝트

별도 사용자 승인 후 새 Vercel 프로젝트를 생성하고 기능 브랜치를 독립적으로 연결합니다. 운영 프로젝트와 도메인, 환경변수, 통합 연결은 그대로 둡니다.

- Root Directory는 `contest-demo`를 지정합니다. 공유 화면과 잠금 파일을 참조하므로 **Include source files outside of the Root Directory**를 사용합니다.
- Framework Preset은 Other, Node.js 버전은 22.x를 사용합니다. 설정 파일은 [contest-demo/vercel.json](../../contest-demo/vercel.json)에 있습니다.
- 설치 명령은 `npm --prefix .. ci`, 빌드 명령은 `npm --prefix .. run demo:build`, 출력 디렉터리는 `dist`입니다. 데모용 환경변수나 서버리스 함수가 필요하지 않습니다.
- SPA 경로 재작성 및 CSP 헤더가 적용되는지 배포 미리보기에서 확인합니다. 발표 전에는 승인된 공개 범위와 별도 도메인을 확인합니다.

## 격리 및 재검증

- `npm run demo:build`는 `contest-demo/dist`만 생성합니다. Vite가 운영 `public/`을 복사하지 않으며 운영 환경 로더나 API 미들웨어를 가져오지 않습니다. 빌드의 모듈 허용 목록은 운영 모듈이나 데이터 클라이언트가 추가되면 빌드를 실패시킵니다.
- 빌드 미리보기의 Network 탭에서 A~D를 진행하면서 외부 도메인, `/api/`, Firebase와 로그인 요청이 없는지 확인합니다. 데모 자체의 필요 외부 도메인은 없습니다. HTML의 `connect-src 'none'`에 더해 배포 설정에서도 같은 제한을 적용합니다.
- 테스트는 `node --test contest-demo/repository.test.js`를 실행합니다. 운영 앱의 빌드 스크립트는 `npm run build`, 전체 단위 테스트는 `npm test`입니다.
